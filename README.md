# Planning Poker

Сайт для командної оцінки задач у стилі Planning Poker.

## Як це працює

1. Юзер заходить на сайт і вводить своє ім'я (без пароля). Ім'я запам'ятовується в браузері.
2. Обирає команду: **BE**, **FE**, **QA** або **BA**.
3. Якщо обрано **BE / FE / QA** — юзер бачить список усіх, хто зараз у цій команді онлайн, поле з назвою задачі, яку зараз обговорюють, і картки з оцінками від 0.5 до 10 (крок 0.5).
4. Якщо обрано **BA** — юзер бачить список активних команд (тих, де є хоча б один активний учасник) і може в будь-який момент примусово відкрити оцінки потрібної команди.
5. Поки не проголосували всі учасники команди (або поки BA не натиснув «Показати оцінки») — голоси одне від одного приховані, видно лише «✓ проголосував» / «… ще ні».
6. Щойно голоси відкриті — всі бачать, хто як проголосував, і середню оцінку команди. Учасники BE/FE/QA можуть далі змінювати свою оцінку — середнє перераховується наживо.
7. Кнопка «Новий раунд» очищає голоси команди і знову ховає їх — зручно для оцінки наступної задачі.

## Технології

- **Backend**: Node.js, Express, Socket.IO (реалтайм через WebSocket), стан — у пам'яті процесу.
- **Frontend**: React + Vite.

Дані (хто онлайн, хто як проголосував) навмисно **не зберігаються в базі даних** — це сесійний інструмент, все живе, поки триває голосування, і скидається при перезапуску сервера.

## Припущення, які я зробив (можна змінити на прохання)

- **Назва задачі**: додав поле для довільної назви задачі, яку зараз оцінюють, — щоб було зрозуміло, за що голосують. Редагувати може будь-хто з учасників команди або BA.
- **«Новий раунд»**: додав кнопку скидання голосів для команди (доступна учасникам команди та BA) — потрібна, щоб оцінювати наступну задачу без перезаходу на сайт.
- **BA і власна команда**: BA не голосує і не входить у список «активних команд для голосування» — він лише спостерігає за BE/FE/QA.
- **Ідентифікація користувача**: прив'язана до поточного з'єднання (вкладки браузера). Ім'я запам'ятовується (localStorage) і команду потрібно обрати заново, якщо перезавантажити сторінку чи прийти пізніше.

## Запуск локально (розробка)

Потрібен Node.js 18+.

```bash
npm run install:all   # ставить залежності і для сервера, і для клієнта
npm install            # ставить concurrently в корені (одноразово)
npm run dev             # піднімає сервер (:3001) і клієнт (:5173) одночасно
```

Відкрити http://localhost:5173 у кількох вкладках/браузерах, щоб побачити реалтайм-синхронізацію.

## Запуск у production-режимі (один процес)

```bash
npm run install:all
npm run build   # збирає React у client/dist
cd server && npm start   # Express віддає і API/сокети, і готовий фронтенд на порту 3001 (або $PORT)
```

## Тести

```bash
cd server && npm test
```

Покриває основну логіку: приховування/відкриття оцінок, автоматичне відкриття коли всі проголосували, примусове відкриття від BA, зміну оцінки після відкриття, «новий раунд», і реалтайм-сценарії через реальні Socket.IO-з'єднання.
